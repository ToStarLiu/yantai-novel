# Copilot 上下文与小说工具契约

日期：2026-11-13。Pi负责模型与工具循环，Go/PostgreSQL负责来源、权限、版本、预算、记录和作者采用。本说明对应实际代码，不将通用对话摘要当成小说事实记忆。

## 信息分层

会话范围固定为`chapter`或`book`。章节轮次固定作品ID、当前章、正文Revision、作品epoch、确认记忆基线、章纲版本以及brief/scenes/arcs版本。启动上下文只提供来源标识、当前章名、章纲前500字、作者选段前1000字和设定名称索引；索引最多24项、名称合计600字，每项最多60字，均明确截断。完整原文保留在Go及数据库，助手按需分页读取。系统指令、作者要求、作品原文、检索来源、候选和摘要分别标注来源，资料中的命令不能改变工具权限。

会话在PostgreSQL持久化。版本边界变化后，旧助手回答、工具结果和摘要退出模型上下文，近期作者意图保留为讨论参考；界面仍能查看原始历史。保留的作者消息可能主动包含旧稿或秘密，因此“重建上下文”不是对作者消息的保密过滤。

同一正文版本只改变选段时保留章级对话，便于继续“解释刚才建议”。启动来源及`read_selection`携带`selectionHash`和`sourceCharCount`，区分当前选择与历史选段任务；当前选择优先，生成选段候选前须重新读取当前完整选择，完整替换锚点由Go冻结并校验。

每次模型请求发送前及工具执行前重新检查来源有效性和项目权限；生成候选在同一事务校验来源、当前对话运行状态、取消请求和租约。工具读取之后即使发生并发修改，下一次模型调用也会在发送前因旧基线被阻断，完成轮次会标记失效。正文候选沿用不可变Revision采用流程：只有作者明确采用后才创建新正文版本。章纲提议同样需作者显式采用并匹配章纲版本。

候选完整正文、Diff和界面制品保留在Go数据库事件与制品中，但工具反馈给模型时仅提供有界内容与候选来源元数据，避免把同一候选正文在内容、制品和Diff里重复塞入窗口。Pi工具消息不再通过`details`夹带完整UI制品，恢复旧会话时也清除该重复字段。原文分页反馈不额外缩短正文而跳过游标；`nextOffset`严格对应已返回的字符。压缩后的实际模型上下文由执行循环结束记录持久化，下一轮延续压缩后的工作记录；原始turn/event档案保持可查看。

## 工具与结果边界

| 工具 | 行为 | 上下文边界 |
|---|---|---|
| `read_chapter` | 读取当前冻结的作者保存正文与唯一选段 | 原文按Unicode字符分页，默认及最大4000；不重复启动章纲/选段预览，返回对应续读工具指针；携带Revision/hash/order |
| `read_selection` | 分页读取本轮完整作者选段 | 默认2000、最大4000字，返回offset/nextOffset/totalChars；原始完整选段锚点留在Go，生成候选时替换完整选段，界面Diff展示真实完整变更 |
| `read_blueprint` | 分页读取完整冻结章纲 | 默认2000、最大4000字，返回offset/nextOffset/totalChars；章纲只代表计划；角色视角模式拒绝读取全知章纲 |
| `read_settings` | 按类型/查询/id选择作者设定 | 每页正文预算3600字（低于4000硬限），最多8项、每项2000字；offset只推进已返回条目，单条id/contentOffset续读；视角模式只按名称查询并返回标识，不返回内容或隐藏长度 |
| `search_story_memory` | 当前章之前的有效定稿检索；可指定角色知识 | 每页最多6条、正文合计2400字/每条400字，标题60字/匹配原因80字；offset续读前50条匹配，原文截断明确标记并可从来源页面核对；保留章节、Revision/hash和误信状态 |
| `check_consistency` | 返回本地确定性规则与确认事实，供当前模型推理 | 每页最多8项事实、值200字/引句120字，值/属性/引句合计2000字；offset续事实、issueOffset续最多4项检查（文本1200字），factId/field/fieldOffset续读完整事实字段，引句有quoteOffset可读原文；semanticReviewPerformed=false |
| `create_revision_candidate` | 保存整章或唯一选段替换后的候选 | 不修改正文；返回独立Run、源Revision/hash及真实段落Diff，计费归当前Copilot模型调用，不额外调用模型 |
| `propose_blueprint` | 保存当前章章纲建议 | 保留规划来源和章纲版本，返回待作者采用的独立Run，不写事实 |
| `show_diff` | 根据冻结原稿和候选计算真实差异 | 校验同作品/同章/当前有效来源；不使用模型提供的字符偏移，不执行修改；大文档使用完整替换hunk限制二次方计算；Node给模型最多6个hunk，每个before/after各250字（最多500字/hunk），总约3000字，diffTruncated/totalHunks标记省略，UI完整Diff不变 |

模型不能通过工具参数替换作品、权限身份、冻结版本或当前章。未声明的参数、未知工具及Shell/文件命令不被执行。viewer/reviewer可读取来源和本地检查；生成正文或章纲候选需要editor以上权限。候选只是作者可审阅的制品，不是模型自行发表、定稿或记忆确认。

## 无章节的全书规划

`POST /api/projects/{pid}/copilot/sessions`传`scope:"book"`即可从零章开始讨论，不创建占位章。全书轮次不接受章节ID、正文版本、选段或角色视角；在同一会话中不能切换范围。会话列表可用`?scope=book|chapter`过滤；书籍和章节对话都只属于创建者，管理员也不能读取其他作者私有对话。共享项目导出不包含私有对话及未采用的全书方案，全库备份包含它们。

全书上下文冻结作品epoch、确认记忆state、brief/scenes/arcs版本，以及作品名称/简介/题材和卷章目录元数据、正文版本指针的散列。因此，即使没有章节，也能验证来源；目录或作品资料变动不会悄悄沿用旧推论。启动上下文不携带整本正文。全书只开放以下四个工具，章节写作/改稿工具不暴露：

| 工具 | 行为 | 上下文边界 |
|---|---|---|
| `read_book_brief` | 读取作者规划、设定摘要和卷章目录 | 概览文字合计约4000字内：brief1800字/规划片段600字、设定摘要最多6项/600字、目录名称1000字预算；目录默认10、最多20项，每项标题40/卷名30字，chapterHasMore与chapterOffset/chapterLimit续读，plotOffset续规划；其他长字段用field/fieldOffset每页2000字完整读取，worldRules/volumes提供JSON文本分页 |
| `read_settings` | 定向读取书籍作者设定 | 类型/关键词/id过滤，offset每页最多8条，正文合计3600字预算、每条1000字；单条长设定通过id+contentOffset续读；角色设定不等于角色已知信息 |
| `search_story_memory` | 作者规划视角检索全书当前有效确认事实 | 每页最多6条、值200字/证据100字，属性60字/主体40字；offset翻页，factId/field/fieldOffset完整续读，保留获知者、truthStatus、来源章/Revision/hash；不读整本正文，不混入未确认或失效候选 |
| `propose_book_plan` | 持久保存独立全书方案供作者审阅 | 最多40000字，按turn/toolCallId幂等；不写正文、不建章节、不修改设定、不确认事实 |

全书候选制品为`book-plan-proposal`，携带`proposalId`及`expectedVersion`。只有候选创建者且当前仍具editor权限，才能经`POST /api/copilot/book-plans/{id}/apply`明确采用。来源轮次必须成功且未失效，作者规划版本和作品基线必须匹配；采用只更新`StoryBrief.plotPlan`，保留作者现有其他结构化字段。重复采用同一版本幂等；作者之后又编辑过则返回409，不能自动覆盖。

## 人物视角的准确含义

显式选择人物视角后，`search_story_memory`强制返回该角色已确认获知的Knowledge投影。模型不能改查另一个角色；不会把旁白段落或证据引句中的秘密混进角色知识。`read_settings`只给实体标识和名称，连查询也不按隐藏内容匹配；全知章纲、作者显式规则和伏笔提示不会通过对应工具进入该模式。

但作者选择给助手阅读的当前正文仍是原文，其中可能包含旁白、其他人物对白和秘密；作者输入也可能主动说明秘密。因此该功能约束写作时的人物知识，**不是保证模型从未接触秘密的隔离沙箱**。模型仍需依据Knowledge状态控制角色言行；原文无法证明角色已经得知某信息。人物知识推理是否符合文学意图仍需模型质量验收与作者审阅。

切换视角会更新上下文基线，清除旧助手/工具/摘要的活动上下文，但保留的作者历史仍可能包含全知说明。需要从未读过作者全知说明的独立讨论时应新建会话并控制输入材料；本系统不宣称具备对已经送入上下文的信息作可靠遗忘的能力。

## 对话压缩与长期记忆

上下文长度是估计值，不伪装成提供商精确token数。先裁剪可重新获取的旧工具大结果并留下来源指针；需要更长对话时，压缩历史讨论，保留作者目标、已接受/拒绝方案、未完成动作、禁止变化、候选Run和Revision指针、未知事项。摘要标记为派生参考，事实引用需要重新读取当前来源。压缩模型调用也须经过同一预算与用量台账，失败不覆盖原始会话。

单个作者请求连续读取多页时，也能压缩已经完成的旧工具交换；保留当前作者原始要求，以及最新完整的助手工具调用与其配对结果，避免切断协议记录。每个模型调用先由Go原子预留同一作品预算，调用完成并记录用量后才可继续；压缩调用也计入该台账。Go拒绝存在Running、Failed或NeedsReconciliation前次调用的轮次再次发起调用。取消会停止子进程；未回报的已授权调用记录为结果未知，不自动重试。即使Pi误报完成，Go也不会将已有未知调用的轮次提升为成功或覆盖原会话。

这采用了[Anthropic上下文工程](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)中按需取材、控制工具结果和压缩长任务记录的思想。[Claude上下文示例](https://platform.claude.com/cookbook/tool-use-context-engineering-context-engineering-tools)将压缩、工具结果清理与持久记忆区分为不同机制，本项目也保留这些边界。

OpenAI的[Compaction指南](https://developers.openai.com/api/docs/guides/compaction)描述提供商的原生压缩协议；本项目为兼容多Provider采用显式派生讨论摘要，没有将它称为OpenAI原生加密压缩。模型和兼容接口的语义表现需另行验证。

## 验证与评估

`internal/workbench/copilot_tools_test.go`的真实PostgreSQL测试覆盖：工具Schema/跨作品拒绝、旧正文和Studio版本拒绝、人物知识/未来章节过滤、只读和撤销权限、候选不写正文/无额外调用、工具幂等、真实Diff、显式采用、章纲版本与取消后候选阻断。`copilot_context_test.go`覆盖完整选段锚点与分页章纲、长正文/章纲/设定名真实Pi运行、单次来源加最大启动快照/指令/工具Schema及call/result配对，使用真实Node estimateTokens验证低于14000（窗口16000），覆盖book/check/正文/设定/两类记忆检索；章节逐字分页与多条长设定完整续读、POV隐藏正文/长度保护、未知调用停止与会话保护。`copilot_book_test.go`和HTTP测试覆盖零章规划、长来源续读、确认/待确认记忆边界、显式采用和私有权限。Pi上下文与协议测试位于`harness/src/context.test.ts`和`runtime.test.ts`（当前17项）；系统执行结果由最终验收记录登记。

固定语义评估输入见`evaluation/fixtures/copilot-context-v1.json`。这些输入覆盖长对话、拒绝方案、版本变更、知识误信和资料注入；文件存在不等于真实模型已通过。客观版本/权限/来源控制由数据库与协议测试验证；“压缩后仍能理解作者意图、人物语言自然”需使用指定模型作独立标注，按用户要求后置文学评价。
