# 评估协议：事实、作者成本与故障行为

状态更新：2026-11-13。本文件保留初始评估协议设计；阶段00已落实为[evaluation/protocol.md](../../../../evaluation/protocol.md)及三轮真实调用基线，阶段04已完成60问关键词评估，故障与隔离测试已在系统中执行。真实模型A/B/C长篇增益、文学效果和作者计时仍未执行，不由工程测试替代。当前结果见[系统验收](../../../release/acceptance.md)。

## 1. 实验配置

| 配置 | 输入组成 | 用途 |
|---|---|---|
| A 基线 | 相同章纲、人工设定、上一章结尾、作者要求 | 接近常规上下文续写 |
| B 状态 | A + 人工确认的结构化叙事状态 | 测量状态的实际增益 |
| C 检索 | B + 带来源与可见性约束的历史片段 | 测量检索增益 |

保持模型、模型配置、章纲和输出上限一致；分别报告实际输入 Token。做额外一次近似等输入预算比较，避免把增加上下文的收益误认为检索算法本身的收益。模型输出不要求逐字重现。

## 2. 样例规模

- 阶段 00：3 章、12 个事实问题、正确/错误草稿各一份。
- 阶段 02：10 章，覆盖位置、伤势、物品、角色知识和伏笔。
- 阶段 03：在同一作品改动两处早期事实，并做一次章节重排。
- 阶段 04：至少 60 个检索问题；40 个开发、20 个保留验收，原始问题和标准答案保存。
- 阶段 06：20 章受控故事与至少一位作者的真实试用；后者不得充当统计显著性的证明。

受控故事为原创测试文本，不使用来源不明的完整版权小说。实际原稿由作者决定是否提供并选择模型服务。

## 3. 核心指标与口径

| 指标 | 计算与记录要求 |
|---|---|
| 事实准确率 | 已确认抽取事实中有明确证据且语义正确的比例；未知不计作正确事实 |
| 必要事实遗漏率 | 当前任务必须使用却未进入有效上下文的标准事实 / 必须事实总数 |
| 问题 Precision | 真正成立的审稿问题 / 系统提出的可判定问题 |
| 问题 Recall | 被发现的标准矛盾 / 人工标注矛盾 |
| 角色知识泄露 | 角色在输入依据不足时使用秘密的次数与位置；同章合理获知不算泄露 |
| 失效索引泄露 | 从旧活动版本或别的作品返回的引用数量，确定性测试要求 0 |
| Recall@10 | 检索前十条覆盖了多少标准相关证据，按问题分别计算再平均 |
| 作者修改时间 | 从阅读候选开始，到作者愿意定稿为止的主动操作分钟数；等待耗时另记 |
| 草稿采用情况 | 全采用、部分采用、弃用及原因；文本变化率只能作辅助 |
| 单章总费用 | 生成、审稿、修订、抽取、Embedding 与失败尝试之和；区分报告值、估算值、未知 |
| 总等待时间 | 排队、模型、重试和索引分别记录 |

不设置“某个词出现即可判断 AI 文风”的通过规则。风格、节奏和可读性由作者评价并说明理由。

## 4. 结果记录契约

```json
{
  "experimentId": "bridge-state-001",
  "fixtureVersion": "bridge-3-v1",
  "configuration": "B",
  "model": "configured-provider-model",
  "promptVersion": "chapter-v1",
  "inputArtifactIds": [],
  "inputTokens": null,
  "outputTokens": null,
  "estimatedCost": null,
  "currency": null,
  "durationMs": null,
  "issueTruePositive": 0,
  "issueFalsePositive": 0,
  "issueFalseNegative": 0,
  "authorEditingMinutes": null,
  "notes": []
}
```

`null` 表示尚无证据或提供商未报告，不等于 0。每份结果链接其输入版本、模型配置、原始输出和人工标注；真实原稿的原始输出默认不提交公共仓库。

## 5. 预定验收门槛

门槛是本次规划的建议值，需要在阶段 00 锁定并记录；之后调整必须保留旧值和原因。

1. 业务确定性检查：跨作品引用、失效版本活动召回、过期状态覆盖和重复状态提交均为 0。
2. 受控错误集：硬事实矛盾检测 Recall 至少 90%，问题 Precision 至少 80%；报告分母与每类结果。
3. 检索保留集：Recall@10 至少 90%，无答案问题不得伪造证据。
4. 10 章与 20 章测试：五类状态均有可追溯样例；两次改稿及一次重排都产生预期影响报告。
5. 作者试用：相同任务下 B/C 相比 A 的修改时间有下降，或在时间相近时明确减少事实错误；逐章报告，不预设改善百分比。

受控集过小或模型波动大时增加独立重复实验。某类失败不能被总分平均掉；关键隔离、数据丢失和过期写入问题阻止发布。

## 6. 必测故障场景

| 场景 | 正确行为 |
|---|---|
| 作者在生成时修改正文 | AI 输出保留为候选，显示输入过期 |
| 页面关闭/刷新 | 任务继续，重新订阅可看到已持久输出 |
| 提供商完成但应用没保存响应 | 标记结果未知，按能力核对，不能默认为免费安全重试 |
| 两个 Worker 竞争一个任务 | 一个有效租约；失去租约的进程不能提交业务结果 |
| 取消与完成同时发生 | 状态转换有明确规则，保留已产生结果与实际费用 |
| 旧章节改变事实 | 相关状态失效，后文提示复核，不自动改写正文 |
| 导出后在空实例恢复 | 内容、版本和来源可读；密钥和会话不随包迁移 |
