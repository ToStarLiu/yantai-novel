# 小说工作台开发计划总纲

初版日期：2026-11-12；状态更新：2026-11-13。阶段00–09按用户授权实施，包含高级功能、Pi作者助手、书籍规划、页面AI配置和跨端交付；作者质量评估与真实试用后置。

## 阅读与执行顺序

1. 阅读[首版设计](../../specs/2026-11-12-novel-workbench-design.md)，确认范围、数据来源规则和任务语义。
2. 按下表执行阶段文件，阶段内以复选框追踪任务，验收后在表中登记证据。
3. 后续阶段开始前，对照已经实现的目录和接口更新计划；变更写入[决策记录](decisions.md)，不得悄悄改变跨阶段契约。

当前已有 Go CLI、API、独立Worker、React Web、PostgreSQL持久化、数据库迁移、Pi Node执行包和受控评估。默认作者路径为书房→新书规划/书籍概览→卷章→写作；全书对话无需先建章节。实现目录按业务聚合于workbench，实际接口与证据见系统验收记录和OpenAPI。

用户追加的完整系统授权优先于首版边界。Typed DAG与PostgreSQL持久执行承担本地长流程，不为替换框架而引入Temporal；本地模型通过原生Ollama适配，不额外捆绑GPU权重。

## 计划粒度

每个阶段文件包含：目标与边界、输入/输出契约、拟创建文件、可检查任务、验证命令、退出标准和故障处置。任务围绕可验收行为拆分，避免把“安装包”“建目录”单独当作业务里程碑。

阶段00–06的原任务列表保留实施溯源，复选框不是当前缺陷清单；各文件末尾调整记录、本文进度表、阶段07/08/09和系统验收共同描述当前状态。原有质量对照、作者计时及未运行部署检查继续保持未完成，不批量勾选历史命令。

## 共同执行规则

- 当前环境没有原计划提及的superpowers技能；按已授权任务和阶段契约执行，并行子代理分工具体模块，最终统一集成验证。
- 关键业务行为先写能暴露错误的测试，再实现；不为纯文档、目录或样式变化编写形式化测试。
- 每个任务完成后登记实际修改、执行命令、结果和残留问题；失败的阶段不标记完成。
- 外部模型实验单独运行并记录费用；离线测试使用假 Provider，不默认消耗 API 额度。
- 首个实现任务检查 Git 是否已初始化；当前规划没有初始化仓库或自动提交。
- 任务验证通过后可以形成独立本地提交；推送、发布等动作按届时用户授权执行。

## 节奏与调整

2026-11-12用户明确撤销作者阅读作为开发前置，要求先完成系统并授权架构优化。工程按实际验收推进；作者文学质量、修改计时与正式试用保留为后续评估，不再阻塞功能实现。

若阶段 00 的真实模型结果无法达到单章基本可用，先调整上下文、Prompt 和模型配置；若阶段 02 的记忆错误率高，优先修正抽取与审核；不通过增加 Agent 或检索系统掩盖已发现的问题。

## 完成定义

本次功能交付需要可运行系统、关键一致性检查、浏览器真实流程、可恢复作品和完整数据库。作者修改时间、文学质量A/B/C对照、Docker新机器实跑单列状态；未执行项不因功能完成而标为通过。

根目录调研文档保留为候选能力来源，技术名不视为必须复制的依赖。逐项目产品优势对应[参考优势矩阵](../../../release/reference-advantages.md)：持久typed DAG、PostgreSQL向量与来源、Electron/PWA分别落实恢复、混合检索和跨端价值；不把未安装Temporal/pgvector/Tauri解释为缺少相应产品功能。Pi层与既有高级页面并存，当前对话工具范围见上下文契约，未宣称所有独立功能都已开放给聊天自动执行。
