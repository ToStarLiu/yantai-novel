# 阶段 00 评估协议

协议版本：`evaluation-v1`；冻结日期：2026-11-12；固定样例版本：`bridge-3-v1`。

本文把设计草案的口径落实为本阶段的执行约定。文档和固定样例已建立；真实模型结果、作者阅读结果与后续阶段指标仍须另行记录，不能因协议存在而写成通过。修改样例、门槛、Prompt 或评分规则必须保留版本、旧值、原因及受影响的实验编号。

## 1. 输入、答案与候选的边界

| 文件 | 用途 | 可作为模型输入 |
|---|---|---|
| `fixtures/bridge-3/story.md` | 起始人物、世界设定和写作约束，不包含秘密答案 | 是 |
| `fixtures/bridge-3/blueprints.json` | 三章章纲；每次只取当前章及其允许前文 ID | 是，但不传未来章纲 |
| `fixtures/bridge-3/chapters/01.md`—`03.md` | 冻结的权威正文 | 依实验任务和叙事位置选取 |
| `fixtures/bridge-3/drafts/correct.md` | 第三章的正确候选对照 | 仅作为本次被审稿 |
| `fixtures/bridge-3/drafts/incorrect.md` | 第三章的错误候选对照 | 仅作为本次被审稿 |
| `fixtures/bridge-3/expected-facts.json` | 人工标准答案、证据、错误标注 | 否，仅供评分和复核 |

`expected-facts.json` 内有 12 个问题：`q01`—`q08` 可回答，`q09`—`q12` 必须承认未知。所有标准答案和未知边界都有正文原句，`firstRevealedAt` 标明首次向读者揭示的位置；角色知情范围另外记录。`q06` 的 `belief` 是林川持有的错误信念，`knownBy` 在该题指知道其错误性质的人，不能据此把林川记为已经知道真相。未知题的 `unknownBy` 表示正文没有支持该角色已知的证据，不宣称已经穷尽了人物尚未写出的经历。

事实问答输入是三章权威正文和问题文本，不提供答案、`answerable` 标签、证据位置或 `knownBy` 标签。输出应包含答案或明确未知及可核对引用。不得用问题答案作为生成所需的“已确认记忆”。

两个候选都替代第三章。审稿输入由起始设定、当前第三章章纲、权威第一/二章及一个候选组成；不把权威第三章作为比较标准，不把另一个候选作为前文。候选中的新增动作只有与前文冲突或违反明确章纲约束才算错误；不能因为与固定正文用词不同就判错。

正确、错误两案使用不同 run、任务意图、输入哈希和产物。若之后引入检索，必须使用不同作品/活动索引组；本阶段没有索引时，两案也不得相互充当上下文。输入快照保存实际拼接后的文本及源文件哈希，不能只记录目录名。

## 2. 阶段 00 执行顺序

1. 校验 JSON 可解析，12 题中 8 项 `answerable=true`、4 项为 false；标准引用是指定文件中的逐字子串；错误句分别存在于错误候选，并不存在于正确候选。
2. 用确定性假 Provider 跑通章纲、生成产物、结构化审稿、保存和失败产物链。假输出只证明工程行为；不能计入模型问题检测或文学质量指标。
3. 用真实 Provider 对同一组冻结章纲重复三次，分别记录每章和整条链的成功、耗时、用量、费用与异常。实验编号必须唯一，完整参数及原始响应可追溯。
4. 分别对固定正确候选和固定错误候选运行审稿；前文和参数保持一致。对实际生成候选另行人工标注，不直接套用固定错误草稿的三个标准矛盾。
5. 人工复核引用、问题成立性、事实答案和未知回答；作者阅读至少一份真实生成稿，记录采用情况与修改负担。没人阅读时该项保持未完成。

真实调用须显式选择配置的 Provider，并在已有接口使用授权和凭据配置下运行。默认测试、故障注入和重试测试均使用假 Provider 或本地 HTTP 服务；它们不能触发真实费用。

本阶段对照使用完整的一、二章前文，标记为 `prefix-diagnostic`。它用于排查来源、角色知识和一致性，不冒充已完成 A/B/C 架构增益比较。

## 3. 后续 A/B/C 对照

| 配置 | 允许输入 | 测量目标 |
|---|---|---|
| A | 当前章纲、人工起始设定、上一章结尾、作者要求 | 常规续写基线 |
| B | A + 已经人工确认且带来源的结构化叙事状态 | 状态对事实连续性的增益 |
| C | B + 通过作品、活动正文版本、叙事位置和角色可见性过滤的历史证据 | 检索的额外增益 |

同一比较固定模型、端点能力、温度、输出上限、章纲、作者要求和 Prompt 版本；配置之间唯一有意改变的是列明的上下文。实际输入/输出 Token、保留和裁剪的来源都需报告。增加一次近似等输入 Token 预算对照，避免将更多文本的收益全部归因于状态或检索方法。不要求模型逐字复现，不能用固定文本相等作为真实模型验收。

阶段 00 无结构化状态与活动检索时 B/C 标记为 `not_run`。阶段 02 使用十章样例对照 A/B；阶段 04 使用至少 60 个检索问题（40 开发、20 保留验收）及 B/C；阶段 06 使用二十章受控故事和作者试用。未来题目不得混入开发调参集，真实试用原稿由作者选择是否提供和发送给哪个服务。

## 4. 事实问题的评分

- 已知题正确：回答语义与标准答案一致，引用确实位于允许正文，未把角色误信当真相，也未把读者已知当成角色已知。表述可以不同；不得以关键词出现一次判定正确。
- 已知题缺失：拒答、答非所问或漏掉决定性限制，例如只说“王都”而未回答机构问题。分别报告缺失与错误，不合并成幻觉。
- 未知题正确：明确表示正文未提供足够信息。可以说明已有边界，如“仍未开箱”，但不能接着给出一个猜测当答案。
- 未知题幻觉：补造箱内物、具体痊愈日、送箱人姓名、绝对日期，或伪造证据。概率词与“我猜”不能把缺乏依据的具体结论变成已知事实。
- 角色知识泄露：角色使用未获知的真相，且当章没有合理的新获知过程。叙述者向读者揭示不等于角色获知；当章有明确披露则不记泄露。

每次运行分别报告：已知题正确数 `/8`、已知题缺失数、已知题错误数、未知题正确拒答数 `/4`、未知题幻觉数和无效引用数。合计 `/12` 可作辅助，不能掩盖未知题全部幻觉或角色知识错误。事实抽取准确率为“有证据且语义正确的已确认事实数 / 所有已确认抽取事实数”；未知和模型置信度不能算正确事实。必要事实遗漏率另算“本任务必须使用却未进入有效上下文的标准事实数 / 必须事实总数”，须保存逐项名单。

## 5. 审稿问题的评分、去重与误报

错误候选含三个独立标注：`injury-disappeared`（伤势消失）、`duplicate-seal-ownership`（同一物品重复持有）、`seal-secret-leaked`（角色知识泄露）。评分器或复核者按语义与来源将问题映射到标注 ID，不能只匹配模型的 `kind`、原句关键词或问题数量。

一个有效命中必须同时具备：候选中确有冲突句、解释指出正确的冲突关系、前文证据支持判断。问题引用存在于输入只是必要条件，不能独自证明问题成立。引用可以是准确的局部子串，但不得断章取义改变人物或语义。

- TP：被有效发现的唯一标注矛盾数，每个标注 ID 每次运行至多计 1。
- FN：未被有效发现的标准矛盾数，等于 `3 - TP`。无效引用对应的问题不能贡献 TP。
- FP：没有标准矛盾或其他经人工确认错误支持的唯一问题。对没有把握的文学意见、无法判定的问题分别列为 `unscored`，不偷偷算 TP 或从所有报告中删除。
- 对同一实体、同一冲突命题、同一来源位置的复述合并为一个问题。重复报告另记 `duplicateIssueCount`，不能用重复同一错误提高 Precision 或 Recall。
- 一条报告同时准确说明多个矛盾时，分别登记它覆盖的标注 ID；它的证据必须分别足够。泛称“全文矛盾很多”不覆盖任何标注。
- 若报告发现三个预置错误之外的新问题，先人工复核。成立则保留为新增真实问题并修订答案版本；同时保留本次冻结三项的 Recall。不得为了总分好看而临时移动分母。

`Precision = TP / (TP + FP)`；`Recall = TP / (TP + FN)`。分母为 0 时写 `null` 并解释，不填 1 或 0。正确候选没有预置硬矛盾，其 Recall 为 `null`；若审稿没有问题，Precision 也是 `null`，另报 `falsePositiveCount=0`。正确候选提出不成立的问题就是误报；风格建议单列，不因不喜欢文风就当硬事实错误。

正式汇总保留每案、每次重复和每类结果。跨实验既报告总 TP/FP/FN 后计算的微平均，也报告各次可定义指标的范围；`null` 不参与平均且需报告缺失数。不得把同一文本重复三次当成九个独立故事错误。

## 6. 本阶段冻结门槛与适用范围

| 检查 | 阶段 00 门槛 | 证据 |
|---|---|---|
| 样例完整性 | 3 章、12 题（8 已知/4 未知）、3 个错误注入，引用均可核对 | 文件版本、验证输出、人工复核记录 |
| 离线工程 | 意图去重、调用前持久化、无效引用拒绝、未知结果不盲重试；相关检查全部通过 | 真实测试命令和结果路径 |
| 固定错误候选的硬矛盾 | Recall ≥90%，Precision ≥80%；逐类报告 | 每次报告与人工标注映射 |
| 固定正确候选 | 硬事实误报数为 0；文学建议另列 | 正确候选独立报告 |
| 事实问答（运行时） | 8/8 已知题语义正确，4/4 未知题明确拒绝补造；伪造引用为 0 | 逐题答案与来源复核 |
| 真实运行 | 同批章纲三次重复，各次成功与失败均有记录 | 模型、Prompt、输入、产物和费用快照 |
| 作者可用性 | 作者阅读至少一份真实草稿，明确表示值得继续建设工作台 | 采用情况、问题和阅读结论 |

三个标准矛盾使 Recall ≥90% 在本样例上实际要求 3/3；报告应直写 `3/3`，不能只写“100%”。三次真实实验逐次报告，某次漏掉任一类别须保留失败并说明调整。更改后重跑使用新实验编号；不得覆盖失败记录。事实问答门槛只用于该任务实际执行的结果；未实现/未运行则写 `not_run`，不因样例有答案而宣称模型通过，也不以此隐瞒阶段验收所需的真实生成和审稿。

以上是受控小样例的进入下一阶段条件，不能证明长篇泛化能力、显著提升或生产可用性。假 Provider 达标只证明程序能执行预设输出，不证明模型能发现矛盾。后续阶段另要求：跨作品/失效版本引用、过期覆盖和重复状态提交均为 0；检索保留集 Recall@10 ≥90%；十章与二十章样例覆盖五类状态、两次回改与一次重排；作者修改时间降低或同等时间下事实错误减少。未实现的后续功能全部标记 `not_applicable_yet`，不计本阶段通过数。

公开结果默认仅提交脱敏摘要和固定原创样例；密钥、私密原稿、完整真实 Prompt/原始响应不进入常规日志或公共仓库。原始证据在受控结果目录保存，摘要引用其位置但不得暴露凭据。

## 8. 故障与未执行项

| 场景 | 预期行为 | 主要验证阶段 |
|---|---|---|
| 同一 intent 重复提交 | 一个业务任务，独立调用有独立 attempt | 00 |
| 外部请求前应用中断 | attempt 已持久；不凭内存日志声称已保存 | 00 起建立，05 加固 |
| 429、无效密钥、非法 JSON | 按原因分类，原始失败可查看 | 00 |
| 请求可能已执行但响应未知 | `NeedsReconciliation`，不自动再发昂贵请求 | 00 起建立，05 核对恢复 |
| 生成时正文换版 | 保留旧输入结果为过期候选，不覆盖当前正文 | 01–03 |
| 页面刷新/关闭 | 任务继续，可重新订阅已保存事件 | 01 |
| Worker 租约竞争、取消完成竞态 | 只有有效租约能提交，明确终态与费用 | 05 |
| 旧稿回改 | 状态与活动引用失效，后续正文只提示复核 | 03–04 |
| 导出后空实例恢复 | 正文、版本、来源一致，不迁移密钥或自动运行旧任务 | 01 初步、06 完整 |

没有数据库、工具链、凭据或服务时记录缺少的条件、实际错误和未执行检查；不得把静态代码阅读、预期输出或模拟结果写成真实数据库/真实模型通过。阶段退出需要区分“实现完成”“离线验证完成”“真实模型实验完成”“作者确认完成”。
